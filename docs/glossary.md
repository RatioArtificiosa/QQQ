# Glossary

Every term QQQ uses precisely. This is **generated** from the Proposal's §0.6 table,
which is normative: where a term is contested in the industry, the definition there
wins for this project.

Each entry links to its anchor in the Proposal, so a reader can see the term in
context rather than only in isolation.


## Host

The native `qqqai` process. Rust. Owns the OS, the scheduler, the network listeners and the secrets. Never trusts the guest.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Guest

A WebAssembly **component** executed by the host.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Component

A binary `.wasm` file in the Component Model format (`version 0x1000d`), with typed imports/exports expressed in WIT. Distinct from a *core module* (`version 0x1`).

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Core module

A classic Wasm module limited to `i32`/`i64`/`f32`/`f64` at its boundaries. May exist *inside* a component.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## WIT

WebAssembly Interface Types — the IDL used to declare component interfaces.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## WASI

WebAssembly System Interface. QQQ targets **WASI 0.3 (Preview 3)**, which introduces native `async`, `stream` and `future` types.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Capability

A *grant* of authority. QQQ components hold only the capabilities explicitly named in their manifest. There is no ambient authority.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Manifest

`qqq.toml`. Declares a project's identity, capabilities, resource limits, interfaces and dependencies.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Lockfile

`qqq.lock`. Resolves the entire dependency graph, with cryptographic digests.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Fuel

A deterministic, portable instruction budget consumed by executing Wasm. Used for metering and for provable CPU limits.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Epoch

A monotonic counter Wasmtime checks at loop back-edges, used to preempt long-running guests without instrumenting every instruction.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Instance

A live instantiation of a component, with its own linear memory and resource handles.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Pool

A preallocated set of memory/table slots from Wasmtime's pooling allocator, enabling microsecond instantiation.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Deterministic mode

An execution profile in which time, randomness, scheduling and floating-point are all seeded and controlled, so a run is bit-for-bit reproducible.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Agent Face

The set of machine-readable surfaces (CLI `--json`, schemas, `qqqai mcp`, error codes, capability reports) designed for AI agents.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## Fabric

The commercial edition: org-wide policy, fleet attestation, SSO/RBAC, compliance evidence, air-gapped mirrors. **Not required to run QQQ.**

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## SLO

Service level objective. Numeric target with a measurement method.

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)

## TTFA

Time To First Answer — from `qqqai new` to a running HTTP endpoint, measured as a user-perceived duration (the launch metric).

[→ Proposal §0.6](../QQQ-Proposal-V1.md#06-glossary)
