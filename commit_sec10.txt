qqq-cap: path traversal passed the containment check (SEC-010, SEC-006, SEC-007)

BUILDING THE TEST CORPUS FOUND A REAL VULNERABILITY. path_is_within -- the
containment check fs_allows uses as its defence-in-depth re-check -- was a pure
string-prefix test whose doc said "Operates on already-canonicalized absolute
paths". Measured, it returned TRUE for every traversal:

  /var/lib/orders/../../../etc/passwd  ->  true
  /var/lib/orders/../secrets           ->  true
  /var/lib/orders/..                   ->  true
  /var/lib/orders/a/../../b            ->  true

It is a prefix check, so it sees "/var/lib/orders/..." and stops. Any caller that
forgot to canonicalize -- or canonicalized a path that DOES NOT EXIST YET, where
std::fs::canonicalize fails -- would have a traversal pass a defence-in-depth
check. A defence that passes the attack it exists to stop is worse than none: it
looks like protection, so nobody adds the real one.

The check is now self-contained: split into components, REFUSE any path containing
"..", compare component-by-component with "." skipped. It refuses rather than
resolving because resolving ".." lexically is subtly wrong -- /a/b/.. is /a only if
b is a directory and not a symlink, and the function has no filesystem to ask.

What it STILL does not defend against is stated in the doc rather than implied:
symlinks. /data/link may point outside /data and a non-canonical path gives no way
to tell. Symlink safety comes from the preopen HANDLE, which is the primary
enforcement; this remains the re-check for a mis-built preopen table.

The corpus is a table so the count is visible, with two controls a one-sided test
could not have: legitimate paths must still be admitted (or a check returning false
for everything satisfies every attack assertion while making every fs grant
useless), and the prefix implementation would have admitted these four (so
reverting to a prefix match breaks TWO tests, not one).

SEC-007's second half was also missing: the epoch test asserted the trap code but
not that the HOST SURVIVES, so "the guest was stopped" was proven and "the host
still works" was assumed. It now builds a fresh instance on the same engine and
runs a benign component afterwards -- the case where a host is most likely to be
left broken, because the interruption came from OUTSIDE the guest's control flow.

SEC-006 is proven by fuel_exhaustion_traps_the_guest_and_the_host_survives plus 40
fuel cases across twenty budgets, because the property is that the classification
does not depend on how much fuel was missing.
